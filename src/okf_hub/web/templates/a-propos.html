À propos de cette interface

Ce site affiche les bases de connaissance d'un hub okf-hub, en lecture seule. Il lit les fichiers et l'historique git des bases sur le disque, et ne fait autorité sur rien : la vérité est dans les dépôts, dont il ne modifie aucun fichier (pas même un verrou git). Toutes ses adresses sont en GET.

Qui voit quoi

{% if web.equipe %}

Mode équipe : l'identité vient du proxy d'authentification de l'organisation, et n'est crue que sur une connexion venue de ce proxy. Une base n'est montrée qu'aux personnes ou groupes que la configuration du hub lui ouvre ; une base que la configuration ne nomme pas n'est montrée à personne. Une base qui ne vous est pas ouverte est introuvable, exactement comme une base absente. Les liens entrants et le graphe ne comptent que les bases qui vous sont ouvertes. {{ nb_visibles|nb('base vous est ouverte', 'bases vous sont ouvertes') }}.

{% else %}

Mode local : pas d'authentification, donc toutes les bases du hub sont visibles ({{ nb_installees }}), et l'interface n'écoute que sur la machine ({{ web.host }}:{{ web.port }}) — elle refuse de démarrer sur une autre adresse. Pour la partager, le mode équipe passe par un proxy authentifié, avec une visibilité par base.

{% endif %}

Ce qu'elle reflète du contrat MCP

Baseskb_list
Explorerkb_find (critères) et kb_search (texte ; avec include_pending, les propositions en attente) — la page donne l'appel équivalent

Graphe, Étatkb_hub_rescan (rapport et dépendances)

Où elle va au-delà, et pourquoi

  • Le corps des propositions est affiché ; kb_proposal_status ne le rend pas, par économie de tokens. Ce texte est une affirmation déposée par une session, à vérifier — pas de la connaissance.
  • Les propositions en attente sont nommées sur les fiches qu'elles mentionnent, toujours marquées « non revues ». L'Explorer les cherche à chaque recherche ; MCP, sur demande seulement (kb_search avec include_pending, même moteur, résultats marqués « non intégré »), et sans les rattacher à aucune fiche.
  • L'historique git (journal, histoire d'une fiche, chronologie) et l'état des dépôts (commits non poussés) : MCP n'expose pas git.
  • Sur MCP aussi, kb_find sait ce que cette interface montre en données : texte, amont modifié, impact par degré, priorité de ré-audit.

Ce qu'elle ne montre pas

  • Les fichiers hors corpus d'une base, sauf GOVERNANCE.md et schema.yaml (page Gouvernance) ; seules les images du corpus sont servies.
  • Aucune page n'écrit : pour contribuer, une session dépose une proposition par kb_propose, qu'un humain revoit.

Glossaire

Les mêmes mots, avec le même sens, sur toutes les pages.

Fiche
Un document de connaissance du corpus. Les fichiers réservés (index.md, log.md) n'en sont pas : ils ne comptent nulle part comme fiches. La page État montre les deux nombres, fichiers et fiches.
Proposition à trancher
Un texte déposé par une session (kb_propose) qu'aucune revue n'a encore intégré ni rejeté. Elle se tranche hors de cette interface, par le rôle gestionnaire. Tant qu'elle attend, c'est une affirmation à vérifier, pas de la connaissance.
Fiche à revérifier
Une fiche qui cite un document d'une autre base modifié après elle : ce qu'elle en dit peut ne plus être vrai.
Priorité de ré-audit
Un ordre, pas un état : l'âge d'une fiche multiplié par le nombre de fiches qui la citent, doublé si son amont a changé.
Manque
Ce que la base devrait contenir et ne contient pas. L'onglet en compte deux sortes : un document qu'au moins une fiche cite et qui n'existe pas, et une proposition de type question encore en attente. La page en montre davantage : ce que le profil déclare sans que le corpus l'ait, et les sections de rôle gaps.
Fiche pilier
Parmi les fiches d'une base, l'une des plus citées par les autres.
Amont
Ce qu'une fiche décline, souvent dans une autre base. Une base déclare les bases qu'elle peut citer (cites) ; l'amont ignore l'aval.
Impact
Les fiches qui dépendent d'une fiche, directement ou de proche en proche : ce qui serait faux avec elle.
Fraîcheur
La date la plus parlante d'une fiche, et d'où elle vient : vérification, production, source, sinon dernier commit.
Gouvernance en brouillon
Les règles de la base (son GOVERNANCE.md) peuvent encore évoluer : les propositions restent acceptées et revues, mais une règle peut changer d'une revue à l'autre.
Base du hub
Une base qui décrit le hub lui-même (comment chercher, retours d'usage), et non un domaine. Elle reste en gris.

Adresses

Stables, pour qu'une autre interface y renvoie : /b/<base>/, /b/<base>/<chemin>.md, /b/<base>/<dossier>/, et les pages d'une base sous /b/<base>/-/ (explorer, manques, gouvernance, propositions, journal, vues). Le segment - sépare ces pages du corpus.
